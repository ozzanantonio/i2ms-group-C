## Session / Week 5 — Building the First Complete User Journey

### 1. Context & Task
- **Goal:** Implement the essential screens, navigation, and state architecture for the MVP user journey:
  - Reporting an urban issue (photo evidence, category selection, location via GPS / map picker / manual entry, and description).
  - Viewing, confirming, and inspecting reports in the public tracker.
  - Interactive map with issue markers and quick reporting.
- **Architectural Requirement:** Separate interface code, application state, and data access using a ViewModel and Repository pattern with in-memory sample data.

### 3. Review, Corrections & Human Verification

1. **LaunchedEffect Message Consumption:**
   - *AI Initial Output:* `LaunchedEffect(vm.message)` consumed the message directly, which prematurely cancelled the coroutine before the Snackbar finished displaying.
   - *Correction:* Decoupled the Snackbar display by launching it inside a dedicated CoroutineScope (`scope.launch { snackbar.showSnackbar(...) }`), preventing early dismissal when `vm.consumeMessage()` clears the trigger state.

2. **Clean Separation of Concerns:**
   - *Review:* Verified that `data/` and `viewmodel/` contain zero hardcoded UI styling or direct Activity references, allowing pure unit testing on the JVM without an Android emulator.
   - *Accepted:* Verified and validated data flows from user click events up to `TicketRepository.tickets` StateFlow.

3. **Privacy & Permissions:**
   - *Review:* Verified that GPS permissions (`ACCESS_FINE_LOCATION`, `ACCESS_COARSE_LOCATION`) are requested lazily only when the user taps "Current GPS", with full fallback to map tapping or manual address typing if denied.
